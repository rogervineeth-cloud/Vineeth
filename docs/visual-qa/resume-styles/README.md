# Resume PDF styles: visual QA

Generated by `npx tsx scripts/render-style-previews.ts` from the fictional
profiles in `__tests__/helpers/resume-fixtures.ts`. Every name, employer and
number is invented. No database or network is involved.

| File | Profile |
| --- | --- |
| `{style}-fresher.*` | Final-year student, no experience, no `section_order`. Shows the fresher fallback: Education, then Projects, then Skills. |
| `{style}-experienced.*` | Two roles, with the generator's experienced order. |
| `{style}-senior.*` | Four roles, dense. This is the profile Compact is designed for, and it stays on one page in every style. |
| `{style}-long-p{n}.*` | Eight roles. More than a page holds, so it paginates and nothing is clipped. |

`{style}` is `classic`, `modern` or `compact`. Each `.pdf` is the real output
of `lib/resume-pdf.ts`. Each `.png` is that PDF rasterised by pdf.js in
Chromium at 900 px wide.

The picker thumbnails in `public/template-previews/{style}.png` are page 1 of
`{style}-experienced.pdf`, rendered at 630 px wide.

ATS properties, enforced by `__tests__/ats-resume-styles.test.ts` for every
style × profile:

- **Real text:** pdf.js extracts every source field verbatim. It extracts no
  words beyond the source, the standard headings and the separators.
- **Reading order:** the content stream reads top to bottom. The name comes
  first, then the contact line, then the standard headings in the resolved
  order.
- **No graphics:** the only drawing is the thin rules. There are no fills,
  images, annotations or form fields.
- **No clipping:** all text sits inside the margins. Dates and locations share
  one right edge.
